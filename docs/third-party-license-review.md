# 第三方内容与许可证审查规范

本规范适用于本仓库对第三方内容的复制、改编、翻译、重命名、vendor、再分发和发布。核心要求是：**按文件或明确的文件路径范围判定授权，不以“整个项目”代替文件级证据。**

## 1. 适用范围

| 操作 | 是否需要审查 |
| --- | --- |
| 从其他仓库或网站复制文件、代码片段、Skill、Prompt、配置或模板 | 是 |
| 将依赖源码 vendor 到仓库，而不是通过包管理器安装 | 是 |
| 翻译、改写、重命名已有第三方内容 | 是 |
| 发布包含上述内容的产物 | 是 |
| 从零独立实现相同功能 | 不需要进行第三方授权判定；仍须为新文件确定许可标识 |

自己从零编写的内容不属于第三方授权判定对象。只要内容起点包含第三方材料，改写或翻译仍然需要审查。

## 2. 判定单位

授权判定按两个维度展开，缺一不可。

### 2.1 内容性质

| 类别 | 典型对象 | 审查重点 |
| --- | --- | --- |
| 程序源码 | `.c`、`.h`、`.py`、`.rs`、Makefile | 文件头、源码许可证、版权声明 |
| 文字内容 | README、`docs/**`、注释散文、Issue 模板、幻灯片 | 文档许可、署名、改编和再发布条件 |
| 数据与配置 | TOML、YAML、Schema、样例数据 | 数据来源、许可范围、是否含第三方内容 |
| 第三方产物 | vendor 依赖、字体、图片、二进制 | 各自的许可证、NOTICE、再分发条件 |

### 2.2 授权证据来源

按审查优先级检查：

1. 文件头部的 `SPDX-License-Identifier` 和版权声明。
2. 明确覆盖该文件路径的 `LICENSE` / `COPYING` 文件及其范围说明。
3. 文件内的版权声明、来源标记和许可文本。
4. README、贡献指南或上游发布说明中的明确声明。

不同来源若存在冲突，应保留冲突证据并暂停判定。SPDX 标识用于表达许可证，不单独证明版权归属，也不能替代署名义务。

## 3. 禁止的推断

| 错误推断 | 正确处理 |
| --- | --- |
| 根目录一个许可证标识自动覆盖全仓库的所有文件 | 检查该许可证对路径的明确覆盖范围，并核对文件级标识 |
| README 写着“本项目采用某许可证”就能证明每个文件均使用该许可证 | README 声明只能作为一项证据，仍需核对文件来源和独立声明 |
| 子目录许可证自动覆盖仓库其他目录 | 子目录许可证仅按其声明的路径范围解释 |
| 文件存在 SPDX 标识就代表署名和通知义务已经履行 | 继续检查版权人、来源、LICENSE 和 NOTICE 等义务 |
| 仓库公开可访问就代表允许复制和再分发 | 未声明许可时按“未声明”处理 |

判定对象必须落到明确路径或 glob，例如 `src/**/*.c`、`skills/vendor-skill/**`。不能使用“整个项目”作为未经证明的文件级判定单位。

## 4. 每条授权结论必须具备的证据

每条结论至少记录以下三项：

1. **上游许可证原文定位**：许可证 URL 或仓库内路径，并标明相关条款。
2. **原始文件证据**：原始文件路径，以及其 SPDX 标识、版权声明或可确认来源的证据。
3. **判定对象**：明确的目标文件路径或 glob。

建议同时记录上游仓库、版本或提交 SHA、取得日期、修改方式、目标仓库路径和需要保留的通知文件。

缺少关键证据时，标记为 **未声明 / 待确认**，停止复制、改编和再分发，并将具体缺项交由仓库维护者确认。公开仓库、搜索结果和沉默都不构成授权。

## 5. 许可证兼容性：不要使用未经核实的结论

许可证兼容性需要结合具体组合方式、目标许可证和分发形式判断。以下是常见规则的边界说明：

| 许可证 | 处理原则 |
| --- | --- |
| MIT / BSD-2-Clause / BSD-3-Clause / ISC | 通常可与 GPL 系列组合；保留原始版权和许可证通知，具体文件仍记录其原始许可。BSD 其他变体需单独核验 |
| Apache-2.0 | 与 GPL-3.0 兼容；与 GPL-2.0-only 不兼容。再分发时保留 Apache 许可证和上游要求的 NOTICE |
| GPL-2.0-only | 不能与 GPL-3.0-only 代码组合成一个受单一 GPL 版本约束的衍生作品；不要将其与 GPL-3.0-or-later 混为一谈 |
| GPL-2.0-or-later | 权利人允许选择后续版本时，可选择 GPL-3.0；仍需核对原始声明 |
| 专有或未声明 | 未取得明确授权前停止复制和再分发 |

**Apache-2.0 与 GPL-3.0 的关系：** GNU 项目将 Apache-2.0 列为可被 GPL-3.0 subsume 的许可证；Apache 软件基金会也说明 Apache-2.0 软件可以纳入 GPL-3.0 项目，但反向将 GPL-3.0 软件纳入 Apache 项目会产生许可冲突。Apache-2.0 与 GPL-2.0 的不兼容，不能错误地扩展成与 GPL-3.0 不兼容。

不要自行编造 `Apache-2.0-exception` 这样的 SPDX 例外标识。SPDX 的 `WITH` 只能引用 SPDX 例外清单中真实存在的标识。Apache-2.0 本身的 SPDX 标识是 `Apache-2.0`。组合项目的表达式应依据实际文件和授权关系确定，不能用虚构例外绕过许可证条件。

权威依据：

- [GNU：许可证兼容性与重新许可](https://www.gnu.org/licenses/license-compatibility.en.html)
- [Apache Software Foundation：Apache 2.0 与 GPL 兼容性](https://apache.org/licenses/GPL-compatibility.html)
- [GNU：GPL 常见问题——GPLv2 与 GPLv3 兼容性](https://www.gnu.org/licenses/gpl-faq.en.html#v2v3Compatibility)
- [SPDX：许可证例外清单](https://spdx.org/licenses/exceptions-index.html)

复杂的代码链接、衍生作品边界、专利条件和多许可证组合应单独审查；不能仅凭许可证名称自动得出结论。

## 6. 作者侧许可标识与当前仓库

### 6.1 新建项目默认值

新建项目默认采用 `GPL-3.0-or-later`。一次性脚本、个人配置和教程仓库可根据实际分发目的另行选择。

这项默认值适用于新建项目，不会自动更改已有仓库的许可证。修改已有项目的许可证必须取得维护者的明确授权。

### 6.2 当前仓库

本仓库原创内容现采用 `GPL-3.0-or-later`。根目录 `LICENSE` 和 `COPYING` 保存完整 GPLv3 文本，README 明确说明适用范围。新增原创 Markdown 文件使用 `SPDX-License-Identifier: GPL-3.0-or-later` 文件级标识。

第三方文件保留其上游 SPDX 标识、版权声明和许可证，不得为了统一项目许可而覆盖上游声明。当前已引入的 `skills/check-the-licence-before-you-copy/SKILL.md` 保留 `Apache-2.0`，其来源、版权人和修改说明记录在 `NOTICE`，完整上游许可证保存在 `LICENSES/Apache-2.0.txt`。

### 6.3 文件标识与通知

对新建的原创文本文件，按文件格式选择正确的注释方式，将 SPDX 标识放在文件头部。常见位置：

- Markdown / 普通文本：首行或文件格式允许的首个注释位置。
- Shell 脚本：保留首行 shebang，在其后添加标识。
- Python：遵守编码声明位置要求，再添加标识。
- 其他源码：遵循该语言通用的文件头注释格式。

对于第三方材料，保留上游版权声明、许可证文本、NOTICE 和来源信息。不要为构建产物、lockfile、生成代码或第三方文件伪造新的所有权声明；具体是否添加标识应依据文件生成方式及上游要求判断。

### 6.4 署名落地

引入第三方材料时，逐项检查：

1. 原始许可证文本是否按要求随分发产物提供。
2. 上游 `NOTICE` 中适用的第三方声明是否保留。
3. 文件级版权、SPDX 和来源信息是否仍然存在。
4. 改编、翻译或重命名后，是否仍能追溯到原始文件和版本。
5. 仓库中的自动化检查是否能发现通知文件或来源标记意外丢失。

如果仓库引入了第三方材料，应为其增加可执行的署名完整性检查；不要只依赖人工记忆。本仓库通过 `tests/test_third_party_attribution.py` 校验 Apache-2.0 许可证文本的 Git blob SHA、NOTICE 来源记录，以及改编 Skill 的文件级版权和来源标识。GitHub Actions 在 push 和 pull request 时执行该测试。新增或移动第三方文件时，必须同步更新测试清单和 NOTICE。

### 6.5 许可变更出口

改用其他许可证、移除上游通知或扩大既有许可覆盖范围，必须取得维护者对当次变更的明确授权。出现证据冲突或许可边界不清时，暂停操作，报告文件路径、证据和未解决问题。
