# 本机与私有项目文档规范

本规范适用于本机开发环境、私有仓库、团队内部系统、个人知识库和 Agent 工作区。公开项目文档遵循 [open-source-docs.md](open-source-docs.md)；GitHub Markdown 排版遵循 [github-content-writing.md](github-content-writing.md)。

## 目标与边界

本机文档帮助维护者可重复、安全地完成环境准备、开发、调试、部署、恢复和迁移。机器信息、内部地址、个人数据、凭据和组织信息不会因写入文档而自动成为可公开内容。发布前应重新判断信息是否适合公开。

## 1. 按生命周期和读者规划文档

~~~text
project/
├── AGENTS.md
├── README.md
├── docs/
│   ├── architecture/
│   ├── development/
│   ├── operations/
│   └── decisions/
└── .local/
    ├── environment.md
    ├── secrets.example.md
    └── experiments/
~~~

| 文档类型 | 推荐位置 | 主要内容 |
| --- | --- | --- |
| Agent 规则 | `AGENTS.md` 或工具入口 | 适用范围、执行约束和验证要求 |
| 开发说明 | `docs/development/` | 依赖、构建、测试和调试 |
| 运维手册 | `docs/operations/` | 部署、回滚、备份和恢复 |
| 设计决策 | `docs/decisions/` | 背景、选项、决策和后果 |
| 本机环境 | 私有目录或本地知识库 | 主机路径、端口、设备和个人设置 |
| 实验记录 | 私有实验或研究目录 | 假设、参数、结果和复现方法 |

按项目规模选择目录，不机械创建全部目录。`.local/` 不会自动成为私有目录；使用版本控制时必须明确配置 ignore，并检查 Git 追踪状态。

## 2. 区分事实、当前状态与计划

- **稳定事实：** 已验证且长期有效的架构、协议、接口或约束。
- **当前状态：** 带时间、版本、设备或环境边界的实际状态。
- **计划：** 尚未实施的目标、候选方案和待办事项。
- **假设：** 需要实验或进一步证据验证的判断。
- **已验证结果：** 记录执行命令、输入、环境、结果和时间。

不要将计划写成现状，不要把一次性的观察概括成永久结论。硬件、软件版本、路径、网络和服务状态发生变化后，应更新带有时效性的文档。

## 3. 记录环境与配置

记录版本、操作系统、运行时、依赖、关键环境变量、端口、数据目录、启动命令和健康检查方式。配置说明区分默认值、示例值和实际值；凭据只使用占位符或 Secret 管理引用。

~~~dotenv
API_BASE_URL=https://example.invalid
API_TOKEN=<set-through-secret-manager>
~~~

不要将真实 API Key、访问令牌、密码、私钥、Cookie、个人身份信息或内部服务凭据写入示例、日志和提交历史。

## 4. 把操作写成可执行流程

重要运维或迁移操作应说明前置条件、影响范围、备份、执行命令、预期结果、失败处理和回滚步骤。破坏性命令应单独标出影响，不与普通检查命令混在一起。

~~~markdown
## 操作前

- 确认目标环境和服务状态。
- 记录当前版本与配置。
- 验证备份可用。

## 执行

说明命令及其作用。

## 验证

说明成功标准和检查命令。

## 回滚

说明恢复路径与数据影响。
~~~

命令应与实际 Shell、操作系统和工具版本匹配。无法验证的命令应标注来源和未执行状态。

## 5. Agent 与自动化规则

Agent 规则应明确适用目录、优先级、允许操作、禁止操作、验证要求和完成报告。把项目级规则放在项目入口；与某个工具或子目录强相关的规则放在对应位置，避免重复维护冲突版本。

规则应可执行、可验证。将“代码要正确”转换为测试、静态检查和验收条件；将“谨慎修改”转换为范围约束、备份和差异审查。

## 6. 实验、故障与设计决策

实验记录包括问题、假设、环境、变量、步骤、数据、观察结果、结论和局限。故障记录区分触发条件、现象、影响、已确认根因、临时缓解和永久修复。设计决策记录背景、约束、候选方案、取舍、最终决策及后续影响。

保留失败结果和不确定性，便于复现与后续比较。避免只记录最终结论而丢失必要上下文。

## 7. 私有信息与发布审查

将本机专属文件、运行产物和敏感数据加入适当的 ignore 规则，并检查它们是否曾被 Git 追踪。`.gitignore` 不会自动取消已追踪文件。

公开仓库或向外部 Agent、插件、服务上传文档前，检查：

- 本机绝对路径、用户名、主机名和网络拓扑。
- IP、域名、内网地址、端口和管理入口。
- Token、密码、密钥、Cookie 和环境变量实际值。
- 客户数据、个人信息、日志和截图。
- 内部架构、合同、业务数据和未公开计划。

发现敏感信息时停止发布，先判断是否需要轮换凭据、清理历史或限制访问。删除当前文件不代表历史提交中的秘密已消失。

## 验收标准

- [ ] 文档说明适用环境、版本和执行范围。
- [ ] 事实、状态、计划与假设明确区分。
- [ ] 关键操作包含前置条件、验证和回滚。
- [ ] 命令、路径、配置键和默认值有来源。
- [ ] 示例不包含真实凭据和个人敏感信息。
- [ ] 私有文件没有被意外纳入 Git。
- [ ] 文档可由目标维护者或 Agent 按步骤复现。
